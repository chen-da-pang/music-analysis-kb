# MERIT 多窗口采样取代首 30 秒单窗

## Status

accepted (2026-10-19); 修订 ADR-0003 中 MERIT 推理配方。来源 spec #123、工单 #127/#129/#131。

## 背景

v1 配方把每首歌**开头 30 秒**送进 MERIT（MERT-330M + rhythm/timbre 头）。听感验收时用户反馈节奏/音色通道"不太对"。

排查结论：

- 两个头没有接反。对同一首歌重算，库里的 rhythm/timbre 与首 30 秒重算结果的余弦都是 **1.000000**。
- 问题是采样：同一首歌首窗与中段 30 秒的向量差异很大（rhythm 余弦 0.676，timbre 0.586）。用 5 首种子歌曲比较首窗与三窗平均，余弦落在 0.81–0.99，timbre 的偏差比 rhythm 更大。
- 另外，验收播放器最初从歌曲 15% 位置开始播放，听众听到的段落和向量采样的首窗不是同一段，进一步放大了"不像"的感觉。

## 决策

1. **MERIT rhythm/timbre 改为三窗采样**：整曲解码后取开头、中点、末尾三个 30 秒窗（`0`、`(duration-30)/2`、`duration-30`；不超过 30 秒的短曲只用一窗）。每窗独立过 MERT 与对应头，头输出的 128 维 L2 归一向量按窗平均，再 L2 归一。
2. **模型身份升级**：模型 id 为 `merit-mert330m-w3-v2`，配方为 `mert330m-l3-4-5-6-23-window3-v2`。旧 id `merit-mert330m-v1` 的模型行保留作历史，但删除其 rhythm/timbre 向量，避免同一通道出现两个有效模型。
3. **查询侧同步**：`runners/audio-embed/evaluate_suno.py` 复用 runner 的 `CHANNELS` 与嵌入函数，因此 Suno 评估自动改用 v2；周更 `audio_embedding` 原子同样复用 runner。
4. **验收播放器对齐**：每首先种子与邻居各给出开头、中段、结尾三段短试听，让耳朵听到的正是向量平均覆盖的三段内容。
5. 整体听感通道（MuQ-MuLan v3）不变。

## Considered Options

- **保留首窗，只改播放器起点**：只能消除"听错段落"，不能消除前奏/主歌偏差，否决。
- **随机单窗**：结果不可复现，验收无法比较，否决。
- **多窗取均值**：计算量约为单窗三倍，但可复现且更接近整曲；采用。

## Consequences

- 434 首 rhythm/timbre 向量需要重算一次（本机约 20–30 分钟），随后重建 v8 快照。
- 历史多版本基准 0.0714 仍只适用于 MuQ 整体通道；MERIT 各通道使用各自的多版本分布（评估脚本已按通道计算）。
- 许可证不变：MERT 权重 CC-BY-NC-4.0，MERIT heads MIT；仍限内部研究用途。
